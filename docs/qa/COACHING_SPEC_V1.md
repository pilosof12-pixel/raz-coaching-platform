# Coaching Specification v1.0 — FROZEN

This is the frozen coaching acceptance contract for launch-quality program generation. It was defined before the next live-generation attempt so the acceptance target cannot move after seeing new outputs.

## Classification policy

- **HARD RULE**: unresolved violation rejects the program.
- **SOFT RULE**: preferred default; alternative programming may be defensible.
- **CONTEXT-DEPENDENT**: depends materially on demonstrated tolerance, training age, schedule, injury history, execution, goals or current performance.
- Software should reject hard-rule violations, steer/flag soft and contextual issues, and repair the lowest-priority stressor first rather than converting every coaching preference into rigid logic.

## Priority-resolution order

1. Safety overrides progression.
2. Primary goal beats secondary goal when stimuli compete for readiness/recovery.
3. Specificity increasingly beats variety near a defined performance target.
4. Recoverability beats theoretical standalone-program volume.
5. Requested frequency may be preserved with low-cost/technical exposures; frequency does not imply every exposure is hard.
6. Maintenance is not improvement: use the lowest reliable preservation dose unless explicit recovery headroom justifies development.
7. When risk/concurrency is elevated, progress one major stress dimension at a time.
8. Demonstrated athlete tolerance may justify exceptions to SOFT/CONTEXT rules, with an explicit reason; it does not silently waive HARD rules.

## Advanced Hybrid hard rules

- **AH-01 Recovery follows goal hierarchy.** High-concurrency athletes must not treat every goal as an independent development block. Three materially progressing qualities trigger review; four or more materially progressing qualities is treated as a hard convergence failure unless lower-priority progress is demonstrably low-cost.
- **AH-02 One true heavy squat exposure, one lower-cost exposure.** When squat is primary and sport load is high, reject weeks where both squat exposures behave like substantial >=80% work. Operational review trigger: both sessions have either >=3 work sets at >=80% with RPE >=8, or >=10 total work reps at >=80%.
- **AH-04 Do not stack demanding local pulling carelessly.** OAP/maximal pulling plus substantial pulling sport work should normally have ~48 h between hard exposures; an adjacent exposure must be genuinely technical/easy (~RPE <=6-6.5).
- **AH-06 Maintenance goals do not receive automatic weekly overload.** Consecutive increases require explicit justification.
- **AH-07 Advanced/high-concurrency load progression is conditional.** Major lift load increases require achieved-RPE/technique/readiness/recovery criteria.

Soft/context defaults retained for generation: intensity-volume tradeoff, secondary pressing typically ~4-8 meaningful direct work sets/week in this concurrent context, labels such as low-cost/primer/recovery must match actual workload.

## Youth / Gymnastics hard rules

- **YG-01 Skill quality ends the exposure.** Attempt numbers are ceilings, not quotas; explicit stop-before-degradation logic is required.
- **YG-03 Rest must preserve skill/power quality.** Do not force conditioning-style rest during acquisition/power work.
- **YG-04 Freestanding-handstand training eventually trains actual balance.** Once basic wall capacity exists, each training week needs reduced-support/independent balance practice.
- **YG-06 Power progresses through output before volume.** Rep increases are a review signal when output/height/speed is not clearly protected.
- **YG-07 Youth work does not default to failure/grinders/forced reps.** Technique and submaximal quality own the progression.

Context/review defaults retained for generation: roughly 8-15 excellent discrete skill attempts/session is a useful default range; full-skill bar-muscle-up practice should appear once prerequisites and safe assistance exist; session content must fit the stated duration including rest/transitions.

## Tactical 3K hard rules

- **T3K-01 Race-primary programming must increasingly expose race demand.**
- **T3K-02 A multi-week trained-athlete 3K block cannot rely exclusively on 200-400 m repetitions.** Include longer race-relevant repetitions/structures during build weeks.
- **T3K-04 Interval pace starts from current demonstrated capacity, not aspirational goal pace.**
- **T3K-05 Protect the key run from lower-body strength fatigue.** Substantial lower-body work within 24 h before the primary quality run is rejected; 24-48 h requires review.
- **T3K-06 Ruck progression changes one major variable at a time: load OR distance OR pace.**
- **T3K-07 Prior lower-leg overuse history requires explicit symptom-gated progression.**
- **T3K-08 When recovery is insufficient, preserve primary 3K work by cutting lower-priority stress first unless safety overrides.**

Context/default guidance retained for generation: roughly 2-4 km of meaningful quality work is a useful trained-athlete interval-session framework; strength maintenance should usually preserve intensity exposure while reducing unnecessary volume.

## Acceptance rubric

Score independently from 0-10:

- Exercise selection
- Loading
- Progression
- Recovery management
- Specificity
- Safety

Default overall score is the arithmetic mean, then apply frozen caps:

- Any unresolved HARD RULE violation -> maximum **7.9/10**.
- Safety <8 -> maximum **7.9/10**.
- Recovery management <7 -> maximum **8.4/10**.
- Primary-goal specificity <7 -> maximum **8.4/10**.

A genuine **9+/10** program must have zero unresolved hard-rule violations, >=8 in every category, >=9 safety, visible primary/secondary/maintenance hierarchy, protected primary-goal key sessions, conditional progression, explicit concurrent-fatigue management, dose matching stated purpose, and a clear response to pain/readiness/performance deviations.

## Change control

This standard is frozen as **v1.0** for the next live-generation cycle.

Any later proposed change must be classified as either:

1. **Specification omission** — a genuinely important principle v1.0 failed to capture; may become v1.1 and must receive regression coverage.
2. **Subjective alternative** — another defensible programming choice; must not count as generator failure when the output already satisfies v1.0.
